# MVP Spec

Status: M1 done (including M1.1, owner's review changes). M2 scope agreed, details in progress (see M2 open questions).

## Goal

Пользователь открывает интерфейс, накидывает system design в конструкторе, читает получившийся документ и при необходимости экспортирует его.

## Milestones

### M1: Canvas + Document

1. **Canvas.** Позволяет быстро накидать system design и удобно смотреть overview получившегося. Отдельный блок можно развернуть и дозаполнить.
2. **Document mode.** Полностью синхронизирован с канвасом: изменение в одном режиме сразу отображается в другом. Документ экспортируется в PDF и Markdown.

### M2: Практическая петля

Цель: замкнуть петлю тренажёра «взял задачу → спроектировал → получил фидбек → повторил». Всё, что эту петлю не замыкает, — в M3 и позже. Детали ниже, в разделе «M2».

3. **Проверка агентом** через готовые скиллы:
   - в режиме канваса — хинты;
   - в режиме документа — комментарии, как в Google Docs.
4. **Аккаунты и облако.** Логин через Google, несколько дизайнов в облаке.
5. **Library.** Два вида элементов: заполненные примеры и задачи (заполнен только Problem Space). Выбор элемента создаёт из него новый дизайн.
6. **Экспорт в Google Docs.** Последней фичей M2: петля важнее.

### M3 и позже

Скоринг, grounding на реальных документах, прогрессия, уровни сложности задач, шаринг по read-only ссылке.

## Decisions

- **Синхронизация: единая модель.** Документ — другое представление тех же данных. Правка Key Properties, Rationale & Notes или Trade-off Matrix в документе меняет блок на канвасе, и наоборот. Свободного текста вне блоков нет.
- **Секции: 9, раскладка по умолчанию 3×3 (D12).** Ряды: Problem Space, Evaluation (Offline), Baseline; Validation, Data & Features, Target Solution & Architecture; Evaluation (Online), Monitoring, Integration; ширины 4 / 3 / 5 колонок в каждом ряду. Карточки можно перетаскивать (менять порядок) и менять им ширину. Раскладка сохраняется вместе с дизайном; Reset layout, Clear design и Load example возвращают раскладку по умолчанию. Канонический порядок секций: Problem Space, Evaluation (Offline), Baseline, Validation, Data & Features, Evaluation (Online), Integration, Monitoring, Target Solution & Architecture. Evaluation Strategy с мокапа переименована в Evaluation (Offline): так точнее. Порядок разделов в документе всегда канонический (этот список) и не зависит от раскладки канваса: раскладка — удобство обзора, документ — рассказ от проблемы к решению.
- **Хранение: только браузер, один дизайн.** Одно рабочее пространство с автосохранением, без списка дизайнов, без импорта и экспорта файла дизайна.
- **Диаграммы: картинка в документе.** Диаграмма Excalidraw показывается в разделе документа как изображение и попадает в PDF и Markdown. Редактируется только в блоке. Экспорт в Markdown: ZIP с `<название>.md` и папкой `images/` (SVG). Если диаграмм нет, скачивается просто `.md`.

- **Trade-offs «заполнены»,** когда в матрице ≥2 варианта, ≥1 критерий, все ячейки заполнены и один вариант отмечен выбранным. Только тогда карточка на канвасе подсвечивает trade-offs как проработанные.
- **Выбранный вариант в матрице и Key Properties независимы.** Итог пользователь сам записывает в Key Properties.
- **Аватары, Share, «Contributors» — вне MVP.** В шапке вместо них кнопки экспорта (PDF, MD).

- **Шаблонные ключи.** У секций есть предзаполненные Key Properties с пустыми значениями. Их можно переименовать, удалить или добавить свои.

  | Секция | Ключи |
  |---|---|
  | Problem Space | Domain, Business Goal, ML Task, Constraints |
  | Evaluation (Offline) | Offline Metric, Loss, Target Value |
  | Baseline | Approach, Baseline Metric |
  | Validation | — (секция может состоять только из диаграммы) |
  | Data & Features | Sources, Key Features |
  | Evaluation (Online) | Evaluation Type (например, A/B test), Key Metric |
  | Integration | Inference Pattern, Output, Latency Budget |
  | Monitoring | Data Drift, Model Quality, Alerting |
  | Target Solution & Architecture | Model Type |
- **Индикаторы на карточке.** Trade-offs и Diagram внизу карточки — индикаторы заполненности, а не кнопки. У каждого индикатора два состояния: погашен или ярко горит. Trade-offs горит только при выполнении строгого правила «trade-offs заполнены» выше, Diagram — если на вайтборде есть хотя бы один элемент. Component Editor открывается кнопкой Details.
- **Стартовое состояние.** Пустой дизайн. Кнопка «Load example» (Churn Prediction, как на мокапе) с подтверждением, потому что перезаписывает единственный дизайн. Тот же пример — фикстура для e2e-тестов.
- **Переполнение карточки.** Показываются первые 4 Key Properties и счётчик «+N».
- **Редактирование в документе — инлайн.** Key Properties, Rationale (тот же rich-text редактор) и Trade-off Matrix редактируются прямо в документе.
- **Пустые секции.** В приложении показываются с плейсхолдером «Not filled yet». В экспорт не попадают; перед экспортом предупреждение, сколько секций не заполнено.
- **Картинки в Rationale.** Кнопка в тулбаре остаётся, но пока это заглушка (неактивна, «coming soon»). Реализация позже.
- **Хранилище — IndexedDB** (сцены Excalidraw тяжёлые, лимита `localStorage` в ~5 МБ может не хватить).
- **Undo/redo.** Только нативный внутри редакторов (TipTap, Excalidraw). Глобального undo нет.
- **Язык интерфейса — английский.** Содержимое пользователь пишет на любом языке.
- **Адаптивная вёрстка** (заменило «только десктоп от 1280px», решение владельца 2026-10-02, D34): все экраны работают от 360px до широких мониторов без горизонтального скролла страницы. Перетаскивание и ресайз карточек — только когда область карточек ≥ 960px; уже́ карточки идут колонкой (две колонки от `sm`) в порядке раскладки.
- **Деплой.** Статическая сборка, которую автор публикует на Vercel. Сборка должна деплоиться на Vercel без бэкенда.

- **Инлайн-правка на карточке.** Значения Key Properties правятся кликом прямо на карточке канваса. Ключи, Rationale, матрица и диаграмма — через Details.
- **Название дизайна** редактируется кликом в шапке («Churn Prediction (Telecom)» на мокапе — пример). В документе название становится заголовком, «ML System Architecture Spec» — подзаголовком. Из названия же берётся имя файла при экспорте.

## M1.1: правки владельца после M1

Эти решения заменяют противоречащие им решения выше.

- **Индикатор Diagram убран.** Наличие диаграммы видно по миниатюре.
- **Trade-offs — значок, а не плашка.** Весы в правом верхнем углу карточки: серые по умолчанию, зелёные с галочкой, когда выполнено строгое правило. Это статус, не кнопка. Всплывающая подсказка:
  - серые: «Trade-offs not filled yet. Weigh the alternatives and make a considered choice.»
  - зелёные: «Trade-offs filled: alternatives weighed, choice made.»
- **Details справа.** Единственная кнопка внизу карточки, прижата к правому краю.
- **Высота карточки по содержимому, ряд — по самой высокой карточке.** Карточки одного ряда одинаковой высоты, так удобнее читать. Пользователь меняет только ширину и порядок, ручки ресайза горизонтальные (слева и справа).
- **Заголовок документа переносится** на несколько строк, а не обрезается многоточием.
- **Safari.** Раскладка канваса в Safari такая же, как в Chrome; приёмочные тесты гоняются и в WebKit.
- **Шапка как на мокапе.** Слева логотип, название, статус сохранения мелким текстом рядом. По центру переключатель режимов. Справа AI Review, Share (всплывашка: Export PDF, Export Markdown) и меню «⋯» (Load example, Reset layout, Clear design).
- **AI Review.** Всплывашка с пунктом «Full review». Пока неактивен, подсказка «Coming soon»; подключение скилла — M2.
- **Свободный текст в документе.** У каждой секции в режиме документа есть поле текста, в том числе у пустых (подсказка «Not filled yet — start typing…»). Текст попадает в Rationale & Notes секции. Пустые подсказки не печатаются и не экспортируются.
- **Заголовок документа редактируется** и меняет название дизайна.
- **Иконки секций.** Target Solution & Architecture — мишень, Baseline — якорь, Evaluation (Online) — колба (эксперимент), Problem Space — флажок. Весы используются только значком Trade-offs, чтобы не путать его с иконкой секции.

## M2

Решения со всеми альтернативами — `docs/decisions.md`, D14–D27. Архитектура бэкенда, схема БД и контракты функций — `docs/backend-spec.md`.

- **Бэкенд — Supabase:** auth, Postgres с RLS, edge functions для вызовов LLM.
- **Логин только через Google.** Базовые scope при входе; доступ к Drive запрашивается отдельно, при первом экспорте в Google Docs.
- **Гость** работает как в M1: один дизайн в IndexedDB, экспорт PDF и MD, экспорт в Google Docs. Нет облака и AI-проверки. При логине локальный дизайн импортируется в аккаунт новым дизайном (облачные не перезаписываются), после чего IndexedDB очищается. «Load example» загружает пример из Library (Supermegaretail Demand Forecasting) вместо Churn Prediction из M1.
- **Несколько дизайнов** у залогиненного пользователя: список, создать, открыть, удалить. Без папок, поиска и переименования из списка.
- **Главный экран** (мокап `mockups/home.html`) — три секции на одном экране без прокрутки страницы: «Design a system» (пустой дизайн или задача из Library) и «Examples» в одном ряду, каждая — горизонтальная лента карточек; ниже «Your designs» занимает остаток высоты и прокручивается внутри.
  - Карточка задачи и примера: превью — мини-карточка Problem Space (Domain, Goal, Constraints, ML Task), название, одно предложение, чип Blank / Task / Example, кнопка действия. У задачи ML Task показан как «Your first decision». У примера — строка Source.
  - «Your designs» у залогиненного — список: карта секций 3×3 в раскладке канваса (заполнена / пуста), название, чип происхождения, ML Task, «N / 9 sections», число trade-offs, открытые находки, дата правки, меню «⋯» (Delete). Последний изменённый — первым.
  - У гостя «Your designs» неактивен: строка «Sign in to keep several designs and run AI review». Над ней, если в браузере есть дизайн, блок «Current work · in this browser» с кнопкой Continue.
  - Гость открывает пример или задачу поверх своего дизайна — подтверждение диалогом M1 («Replace your current work?»), затем перезапись. Залогиненный — первая правка примера сохраняет его копию в «Your designs».
  - Шапка: у гостя — дефолтный аватар (`mockups/assets/default-avatar.png`) и «Sign in with Google»; у залогиненного — фото из Google. Аватар стоит левее кнопок, как на `mockups/canvas.png`.
- **Хранение дизайна** — один JSONB-документ на дизайн, та же модель, что в M1. Одновременные правки: last-write-wins с проверкой номера версии дизайна (D23) и баннером «изменено в другом месте, перезагрузить». Без realtime-синхронизации.
- **AI-проверка — только после логина, BYOK.** Ключ пользователя хранится зашифрованным в Supabase Vault, клиент может его записать, но не прочитать. Лимиты расходов пользователь ставит у провайдера.
- **Проверка запускается по кнопке** (весь дизайн или одна секция), а не автоматически. Повторный запуск не отличается от первого: новые находки заменяют все находки в скоупе запуска.
- **В проверку уходит весь дизайн,** включая диаграммы как PNG (мультимодально). Problem Space — это условие задачи, отдельного условия нет.
- **LLM через OpenRouter.** Пользователь хранит ключ OpenRouter и выбирает модель. Скилл от провайдера не зависит, прямые адаптеры провайдеров можно добавить позже.
- **Находки привязаны к полю модели** (секция, Key Property, строка trade-off матрицы, Rationale), а не к диапазону текста. Одна находка — хинт на карточке и в Component Editor и комментарий на полях документа. Статусы: open, resolved, dismissed; после правки поля находка помечается stale. Если поле удалено, находка переезжает в общий комментарий к дизайну со статусом stale.
- **Статус находки один на весь дизайн.** Resolve, Dismiss или Reopen в любом месте (панель Review на канвасе, Component Editor, комментарий на полях документа) сразу отражается во всех остальных: бейдж и индикатор ревью на карточке, маркер у поля в Component Editor, комментарий в документе, счётчики и вкладки Open / Resolved / Dismissed. Без перезагрузки и переключения режима.
- **Документ: оглавление слева, комментарии справа**, как в Google Docs. Так всегда, а не только при открытом ревью; это отличие от `mockups/document.png` и от M1. Вид оглавления остаётся как в M1.
- **Отображение ревью** (мокапы `mockups/review-canvas.html`, `review-editor.html`, `review-document.html`). Три уровня: сигнал (где и насколько плохо) → заголовок находки → полный текст по клику.
  - Severity из скилла: Critical, Major, Minor. Точка: critical — сплошная красная, major — красное кольцо, minor — серая.
  - Карточка канваса: в шапке рядом с индикатором trade-offs — индикатор ревью (лупа) того же вида. Серый — секцию не проверяли; красный с «!» — есть открытые critical или major; зелёный с галочкой — проверено, открытых нет или остались только minor. В футере слева — бейдж «● N findings» (точка по худшей severity), если есть открытые находки; клик открывает панель Review на этой секции.
  - Панель Review справа на канвасе: счётчики по severity, вкладки Open / Resolved / Dismissed, группы по секциям в каноническом порядке, первой — «Whole design». Внутри группы — по убыванию severity, minor свёрнуты строкой «N minor — show». Раскрытие находки подсвечивает и прокручивает к карточке.
  - Component Editor: справа колонка Findings только этой секции с теми же вкладками; маркер-точка у поля (у Key Property справа от значения, у строки матрицы после названия варианта, у Rationale рядом с заголовком). Клик по маркеру раскрывает находку, клик по находке подсвечивает и прокручивает к полю. В шапке — тот же индикатор ревью.
  - Документ: комментарий на высоте своего поля, при наложении сдвигается вниз; раскрытый встаёт точно напротив поля, поле подсвечивается. Находки по дизайну целиком — напротив заголовка документа.
  - Находка: заголовок, severity, поле и измерение рубрики; раскрытая — «What the design says», «Why it matters», Fix свёрнут за «Show fix» (сначала пусть подумает сам), кнопки Dismiss и Resolve. Закрытая — с кнопкой Reopen. Stale — бледнее, с меткой «Field changed since review» или «Field removed».
  - Dismiss и Resolve только меняют статус, без причины и без проверки. Повторный запуск заменяет находки скоупа, поэтому отклонённая может вернуться — принято для M2.
- **Запуск ревью и настройки ключа** (мокап `mockups/review-run.html`).
  - Меню AI Review: «Review whole design» и «Review one section» со списком 9 секций; внизу модель, время последнего запуска и ссылка Settings. Без ключа — «Add your OpenRouter key» с кнопкой «Add key». Гостю — «Sign in to run AI review». В Component Editor в колонке Findings кнопка «Review this section».
  - Настройки — диалог «AI Review settings» из меню аккаунта (My designs, AI Review settings, Sign out) или по ссылке Settings. Ключ: поле-пароль и Save; при сохранении проверка запросом к OpenRouter («Checking…»); после — только `sk-or-v1-••••a3f9`, «✓ Works», Replace, Delete; отклонённый ключ — красное поле и подсказка. Модель: список только моделей с картинками на входе и structured output, по умолчанию рекомендуемая. Цены моделей не показываем.
  - Ход проверки: панель Review с плашкой «Reviewing … 0:24», полосой и Cancel; индикаторы ревью карточек в скоупе пульсируют индиго; прежние находки видны бледно до замены. Править дизайн во время проверки можно, изменённые поля станут stale.
  - Ошибки — плашкой в панели, прежние находки не трогаются: ключ отклонён (Replace key), нет кредитов (Run again), rate limit (Run again), модель не принимает картинки (Choose model), ответ не в формате находок (Run again), ревью дольше 2 минут (Run again), ревью уже идёт, 20 ревью за час. Тексты — `docs/backend-spec.md`, §6.4.
- **Находки не попадают в экспорт** (PDF, MD, Google Docs): экспорт — артефакт решения, а не ревью.
- **Вывод скилла — в чистом виде, включая «Fix».** Пока нет инфраструктуры под тренировки, помощник не переформулирует исправления в вопросы. Gradecard и вердикт не показываются: оценки — в M3 вместе со скорингом, своим UI и сохранением для прогресса.
- **Находки по измерениям рубрики без своей секции** (Cost of mistakes & risk, Error analysis, Training pipeline, часть Prior work & baselines) идут в общий комментарий к дизайну.
- **Library** — элементы лежат в `docs/library/`, по файлу на элемент, в разметке по 9 секциям (Key Properties, Rationale, Trade-offs с выбранным вариантом, описание диаграммы). В прогоне M2 агент переводит их в фикстуры в `src/fixtures/`, как `example.ts` в M1. На старте один пример (`retail-demand-forecasting.md`, он же «Load example» и фикстура e2e) и одна задача (`superpay-fraud-detection.md`). В задаче ML Task пустой: выбрать его — первое решение пользователя. Таблиц в Rationale нет (редактор их не поддерживает), вместо них списки. У элемента есть поле Source, Library его показывает (пример взят из репозитория ML-SystemDesign под MIT).
- **Пример заменяет Churn Prediction.** Acceptance-сценарии M1 (AT-11) проверяют название «Churn Prediction (Telecom)». Сценарии M2 пишет автор и учитывает новое название; пример, как и Churn, заполняет все 9 секций, полные trade-offs в 7 секциях, диаграммы в 3.
- **Экспорт в Google Docs** — HTML документа загружается в Drive с конвертацией в Google Doc, scope `drive.file`. Диаграммы растеризуются в PNG.
  - Мокап `mockups/export-gdocs.html`. Share: первым пунктом «Export to Google Docs» (подпись «Creates a new Google Doc in your Drive»), затем Export PDF и Export Markdown.
  - Каждый экспорт создаёт новый Google Doc, прошлый не перезаписывается: в нём могут быть правки команды. После экспорта в меню Share строка «Last exported …» со ссылкой Open.
  - Статус — уведомлением внизу по центру: пока открыто окно Google — «Continue in the Google window…»; затем «Exporting to Google Docs…»; готово — «Google Doc created» с Open и Copy link. Ошибки с Try again: доступ не дан (ничего не экспортировано), окно заблокировано браузером, Drive не принял документ (PDF и Markdown работают).
- **Режимов Training / Real-Work нет:** разницы между ними нет, среда одна.
